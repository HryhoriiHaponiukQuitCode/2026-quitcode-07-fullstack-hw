# Здача WS7

Здача — **один PR у цей репозиторій з одним новим файлом**:

```text
submissions/<team-slug>/<github-login>.md
```

- `<team-slug>` — `property-workflows`, `therapy-scheduling`, `school-purchasing` або `leave-portal`;
- `<github-login>` — ваш логін GitHub, точно як у профілі (той самий, з якого відкрито PR);
- вміст — за [шаблоном](_template.md), усі поля заповнені, зайва для вашої ролі частина — «—».

Здає кожен окремо: PM і кожен розробник — свій файл. Роль у файлі — `pm` або `dev`. Інших файлів PR не змінює: ні
README, ні `docs/`, ні `materials/`, ні чужих файлів у `submissions/`. **Строк — до кінця Вт 27.10** (23:59 за Києвом).

## Яке репо й SHA вказати

Кожен здає **своє** репо — те саме, що у WS6:

| Роль | «Ваше репо» | «Репо вимог PM» |
|---|---|---|
| `pm` | репо вимог `https://github.com/<pm>/<team-slug>-spec` | те саме |
| `dev` | своє репо `https://github.com/<dev>/<team-slug>` | репо вимог PM вашої команди |

Конвеєр перевіряє «Ваше репо» **на цьому коміті**, тому коміт має бути запушений, а SHA — повний (40 символів): коміт
`main` вашого репо на момент здачі.

- **Розробник:**

  ```bash
  git fetch origin
  git rev-parse origin/main
  ```

- **PM (без git):** на сторінці репо вимог відкрийте історію комітів `main` і скопіюйте повний SHA останнього коміту
  кнопкою копіювання біля нього (точну назву перевірте в інтерфейсі). Короткий SHA з 7 символів не підходить.

## Посилання — у якому вигляді

| Що | Де | Вигляд |
|---|---|---|
| PR | ваше репо | `https://github.com/<ваш-логін>/<repo>/pull/N` |
| Файл або тека на SHA | ваше репо | `https://github.com/<ваш-логін>/<repo>/blob/<SHA>/DESIGN.md`, `…/tree/<SHA>/openspec/changes/…` |
| Прогін CI (зокрема червоний прогін мутації) | ваше репо | `https://github.com/<ваш-логін>/<repo>/actions/runs/N` |
| Issue «Продукт», «Вимога», «Питання до вимог» | репо вимог PM | `https://github.com/<pm>/<team-slug>-spec/issues/N` |
| Коментар в issue («Зміна: …», «Перевірено за чеклістом: …», ваше питання) | репо вимог PM | `…/issues/N#issuecomment-M` |
| Варіант `docs/`: файл вимоги, рядок, коміт, коментар до коміту | репо вимог PM | `…/blob/<SHA>/docs/requirements/02-….md`, `…#L40`, `…/commit/<sha>`, `…/commit/<sha>#commitcomment-M` |
| Issue «Відхилення від вимог» (таблиця приймання PM) | репо розробника | `https://github.com/<dev>/<team-slug>/issues/N` |
| Тест у таблиці приймання PM | репо розробника | `https://github.com/<dev>/<team-slug>/blob/<sha>/tests/…#L10` (на коміті, не на `main`) |

**Паролів у файлі немає ніде:** акаунти — лише адреси `*@example.test`.

## Покроково: розробник

```bash
gh repo fork koldovsky/2026-quitcode-07-fullstack-hw --clone
cd 2026-quitcode-07-fullstack-hw
git switch -c ws07/<github-login>
cp submissions/_template.md submissions/<team-slug>/<github-login>.md
# заповніть файл
git add submissions/<team-slug>/<github-login>.md
git commit -m "WS7 submission: <team-slug>/<github-login>"
git push -u origin ws07/<github-login>
gh pr create --repo koldovsky/2026-quitcode-07-fullstack-hw --web
```

PowerShell: `Copy-Item` замість `cp` (або `cp` — у PowerShell це той самий alias).

## Покроково: PM (у браузері)

1. Відкрийте [шаблон здачі](_template.md) в цьому репозиторії, перегляньте сирий текст (кнопка Raw; точну назву
   перевірте в інтерфейсі) і скопіюйте його повністю.
2. Перейдіть у теку `submissions/<team-slug>/` цього репозиторію → Add file → Create new file (точні назви перевірте
   в інтерфейсі). GitHub попередить, що права запису у вас немає, і запропонує працювати у вашій копії (fork) — це
   правильно.
3. Ім'я файлу — `<github-login>.md`, вміст — скопійований шаблон. Заповніть поля просто в редакторі. Таблицю
   приймання (трек D) можна спершу заповнити в нотатках, а потім вставити: рядок на кожен прогнаний AC під кожною
   роллю.
4. Внизу оберіть створення нової гілки й запропонуйте зміну (Propose new file → Create pull request; точні назви
   перевірте в інтерфейсі).

## Далі — для всіх

Fork цього репозиторію потрібен **лише для здачі**. Ваша робота живе у вашому репо вимог чи репо розробника.

1. Відкриється сторінка нового PR з шаблоном опису. **Заголовок — `WS7: Ім'я Прізвище`.** У шаблоні заповніть
   **«Ім'я та Прізвище»** (обов'язково: сертифікат виписується на реальне ім'я) і роль. Розробник не додає `--fill`:
   з ним опис береться з комітів, і шаблон не підставляється.
2. Цей репозиторій має менше 10 зірок, тому CodeRabbit не почне сам. Напишіть у PR **окремим коментарем**
   `@coderabbitai review`.
3. CodeRabbit перевіряє лише файл здачі: шлях, заповнені поля, SHA, рядок «Вимоги:», вигляд посилань, відсутність
   паролів і що нічого іншого не змінено. Виправте зауваження в тій самій гілці: розробник — новим комітом і push,
   PM — правкою файлу у своїй копії (іконка олівця на сторінці файлу; точну назву перевірте в інтерфейсі).

Ім'я та прізвище — лише в описі PR, не у файлі: файли цього репозиторію публічні.
